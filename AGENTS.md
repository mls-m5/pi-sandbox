# Working on pis

Use **[docs/development.md](docs/development.md)** for the compact implementation map, verification boundaries and pending work; keep durable details in their feature documents, not per-agent handovers. Use README.md for normal setup and docs/host-actions.md for approval/security contracts.

- The core is a dependency-free Node.js ES-module CLI; optional web dependencies are isolated in `web/`. Run `npm run check` after code changes.
- Subagents may use only Luna: explicitly set `model: "openai-codex/gpt-6-luna"` for every delegated run, including reviews and resumed workflows. Never inherit the parent model or substitute another model. If Luna is unavailable or cannot perform the task, the current main agent must do the work itself rather than delegate to another model. This restriction avoids expensive subagent token usage; it does not itself authorize delegation.
- After substantial changes, proactively create small, coherent, descriptive commits at verified milestones rather than accumulating a large uncommitted tree. Inspect `git status`/diffs first; preserve others' work and never stage credentials, generated dependencies or unrelated files. Clearly identify unfinished scaffolding and verification gaps instead of presenting it as finished functionality.
- Users handle Git pushes manually. Agents make small verified local commits and report their hashes; do not call `request_host_git` or propose pushes unless the user explicitly asks again. Never push directly.
- Dependency cooldown: never bump or add an npm package, pinned Pi/Claude Code/extension version or lockfile entry whose release is less than 7 days old (check the publish date, e.g. `npm view PACKAGE time --json`). Pin exact versions and keep lifecycle scripts disabled. If a security fix needs a newer release, say so and let the user decide. The managed updater enforces the same 7-day minimum in `src/updates.js`.
- Fast tests make no paid model calls. Real-Podman integration tests are opt-in and use fake upstreams. Do not make paid/live model requests or external Git pushes as casual smoke tests.
- In a sandbox the shared repository is writable, but host credentials/config, GNOME and Podman control are not expected to be accessible. Experimental Claude Code mode keeps its global subscription token in host auth storage behind a Claude-only host proxy reached via a private Unix socket; containers get only Claude Code's fixed placeholder. Never mount host Claude state or credential files, never give the Claude proxy to Pi, and never accept API keys for it. See docs/claude-code.md. Do not bypass this by mounting host home, agents or container-engine sockets.
- `request_apt_packages` and `request_host_git` are image-owned tools for **proposals**. Only the host can approve. Git currently allows exact-commit pushes only; do not turn this into a shell or unrestricted Git-command interface.
- Preserve explicit project configuration. Never print auth files, API keys, full process environments or credential-bearing URLs. Do not log out, revoke or replace provider credentials as a troubleshooting shortcut without a fresh user request.
- Web controller/server/connectors run on the host, not in an OS sandbox; only real Pi tools retain the existing Podman boundary. Same-host independent enrollment is implemented via --server --standalone and --connect, with private per-port persistent standalone server registrations and private host client profiles (browser sessions/approvals stay ephemeral; non-standalone stays memory-only); bare --connect uses a saved host-global origin and the current registered Pi project, then displays a two-digit client code for authenticated approval under Väntande klienter. Approval/collection are bounded, session-bound and one-use; the code alone is not authentication. --set-server saves only the private address, --server overrides it for one run, and legacy GUI keys remain explicit via --enrollment-key/--key-stdin. Explicit ssh://[USER@]HOST[:SSH_PORT][/PIS_PORT] (defaults 22/43128) creates one host-owned strict-key SSH forward via a private Unix socket; direct HTTP remains loopback-only and exact Host/Origin checks remain intact. No saved address prompts interactively and saves the validated answer. SSH host auth/config stays outside agent containers; no password prompts, host-key bypass or raw SSH stderr diagnostics. --forward ssh://[USER@]HOST opens a separate browser-only 127.0.0.1 listener (local port equals remote pis port, default43128), prints a link and fails on port conflicts; no random/public bind or Host/Origin rewrite. It changes no project/profile and stops its owned forward on Ctrl-C/failure, not remote agents. Offline identity reuse requires prior-key proof; never evict a live agent or replay ambiguous enrollment. See docs/web-agents.md. Separate least-privilege server isolation, direct TLS/LAN deployment, persistent admin login maintenance, remote apt approvals/generic host operations and supervisory continuation remain future work. Narrow web Git-push approval now requires explicit per-launch --allow-web-git on the owning Pi host; enrollment never grants it. Reuse stopped-container verification/private snapshot/exact commit, bind browser review nonce/session/generation/proposal, never force or auto-retry/task-resume. Only a correlated terminal Git outcome plus separate post-cleanup host IPC marker and zero wrapper exit may replace Pi once with a fresh idle runtime/new generation, keeping the connector/key/SSH transport alive. No old prompt/queue/push replay or crash-restart loop; explicit close/unconfirmed cleanup/failed replacement suppress recovery. Previous-generation Git results are read-only, never new approval authority. Individual absorbed submodules must remain inside project .git/modules; no recursive push or arbitrary .git pointers. See docs/host-actions.md. SSH forwarding has fake-transport tests, not real OpenSSH/multi-computer certification. Do not silently enable production quota-auto in RPC or interpret idle as goal completion.
- Keep web startup/diagnostics content-safe: fixed phase/error codes and generated references only, never raw stderr/auth/history/request payloads. Generated CLI admin passwords and the requesting client's short-lived two-digit confirmation code are explicit terminal-display exceptions (never machine keys); never ask users to share entire terminal logs, auth/state directories or HARs.
- Web history is bounded and fetched from the agent when opening a view or manually refreshing, independent of state/live control. The controller has no persistent transcript store. A history size limit must reject only that known read while draining to LF, not kill the agent or erase persisted sessions. Preserve ordinary-record limits, strict framing, request correlation and no automatic replay after ambiguous outcomes. Read docs/pi-rpc.md before changing parser limits.
- Web steering is explicit: known idle form submissions are prompts, known working submissions are native steer. Browser steer/follow-up drafts are bounded and agent/generation scoped, not persisted or automatically drained. take_queue confirms destructive native clear_queue to recover remaining bounded exact text; never retry ambiguous queue delivery/retrieval or mark duplicate replies as confirmed sends. Stop still clears native queue before abort; local unsent drafts are separate. See docs/pi-rpc.md and docs/web-control.md.
- GUI server updates are standalone-only under the foreground supervisor, explicit admin-confirmed clean-tree public HTTPS GitHub fast-forwards. Never extend this into arbitrary Git/shell or an agent-selected path. No auto-install, crash restart, destructive rollback or scheduled update; dependency/supervisor changes remain manual. The parent retains only a salted password hash in memory across explicit restarts; browser sessions/approvals expire. See docs/web-control.md for limitations/host verification gates. Web Git-push approval is separate and requires explicit per-launch host opt-in; never use the updater's authority for agent Git.
- Pending requested feature: host-global Git name/email defaults in the sandbox; see docs/git-identity-plan.md. It is not implemented yet.
- Update documentation when changing defaults, approval flow, restart notifications, cleanup policy or credential handling. Clearly distinguish tested behavior from plans and host-local changes.
