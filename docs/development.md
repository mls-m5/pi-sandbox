## Current web/history issue and implemented mitigation

Host diagnostics confirmed a real Pi project starts/answers state/registers successfully, but `get_messages` exceeded the ordinary 4 MiB native record cap (`rpc_record_too_large`). That previously faulted the adapter, causing later state requests to fail too. Dummy end-to-end state/history/prompt reads were confirmed by the user's safe traces; those successful traces are not a general graphical-browser certification.

The web UI automatically opens the first roster agent. Opening/reopening an agent or reconnecting reads **state first**, follows live events and automatically requests bounded recent history once. Fresh idle state enables prompt/stop independently while history is pending; failures remain nonfatal with manual **Hämta senaste historik** refresh/retry. Settlement checks remain state-only: no history polling, failure retry loop or prompt replay. State readiness and displayed-history completeness are separate; history failure alone must not prevent valid idle prompt/stop control. The requested native history reader retains at most 100 messages/1 MiB of raw recent bodies before existing 256 KiB projected-view limits. It uses a separate bounded streaming path; an over-limit history read drains to LF and rejects only that read with `rpc_history_limit`. Ordinary malformed/unsolicited/oversized non-history records still fault closed. Full native history may still traverse the pipe on each automatic/manual history request; there is no native paging command or full session-file reader. Saved session/context/compaction policy are unchanged. See [the detailed parser limits](pi-rpc.md).

The user reports the updated web flow now works. This is useful host feedback, not exhaustive verification of every giant-history edge case or production container lifecycle. No need to reset auth, delete transcripts, recreate a project or increase record caps without bounds.

Assistant reply text has bounded fixed-DOM Markdown (headings/emphasis/code, lists, disabled task checkboxes, pipe tables and explicit HTTP(S) links); user/thinking/tool content stays literal. Content text uses textContent; links alone get separately validated href/new-tab/no-opener/no-referrer properties and require a user click. Raw HTML, images, unsafe URL schemes, remote highlighting and arbitrary attributes stay disabled. Checkboxes cannot mutate agent work. The implementation/security contract is in docs/web-control.md; formatting tests run without model calls.

Completed assistant replies now show only Pi-reported numeric per-reply token usage (input/output/cache/total); this is not remaining subscription quota and makes no provider request. Missing usage stays absent/unknown; prices/provider metadata remain omitted.

Agent activity display decisions are pure/ordered in `web/public/activity.js`, separate from runtime lifecycle and control readiness. Agent activity has a text-labelled work/wait spinner (CSS respects reduced motion); idle is explicitly not task success. Tool call IDs/results are retained in the bounded client projection and merged into one chat card: dashed running, blue completed, red reported error, neutral unknown if completion was missed/interrupted. Result text stays literal, arguments omitted. Agent-end alone does not stop the activity indicator; settlement does. See docs/web-control.md for history/live limits and verification gaps.

Berget model overlays now use `src/berget-models.js`: one bounded unauthenticated public GET per launch, fixed endpoint/no redirects, five-second deadline, compatible streaming/tool chat filtering and a four-chat-model bundled fallback. `discoverModels: false` opts out; Berget-only `modelOverrides` supply explicit verified metadata. The public response omitted context/output limits, so local default output budgets are not certified provider limits; EUR prices are not copied as USD. GLM's default is now 320000 context (Berget GA announcement) / 65536 output (local reasoning+answer budget, increased from 8192 after reported length truncation). Valid discovered limits then explicit overrides win. Effort-control metadata is not proof that server reasoning is off; no unverified Berget effort parameters were added. An injected-fetch Pi AI 1.5.2 probe confirmed 65536 reaches the wire and synthetic reasoning_content parses as thinking without external requests; image pin remains 1.5.0 and live Berget behavior is still unverified. Read docs/proxy.md before changing this boundary. Fake upstreams disable public discovery unless a catalogue-fetch fake is injected.

Standalone local enrollment is implemented in `web/agent-cli.js`, `web/agent-profile.js`, `web/pairing.js`, `web/pairing-client.js` and admin-only server routes. `pis --server --standalone` starts no runtimes; the GUI creates/revokes registrations (standalone persists metadata/key hashes privately per port) and shows keys once. Default `pis --connect` resolves the current registered Pi project and saved host-global server address; a client-displayed two-digit code is entered under **Väntande klienter** by an authenticated admin. Explicit name/project/server overrides remain. Approved collection issues one machine key, safely replaces its private profile and starts the agent. `--set-server` saves only the private address; old GUI-key enrollment remains behind `--enrollment-key`/`--key-stdin`. The GUI no longer pre-names agent placeholders. Tickets expire after ten minutes/issuer logout and cannot connect as agents; redemption returns a distinct connection key. Stable local client IDs plus prior-key proof reuse an offline registration; active identities are refused rather than displaced. Duplicate labels receive numeric suffixes; no prompt/ambiguous enrollment is automatically replayed. Advanced legacy register/run/forget remain supported. Preflight and existing project locks still gate runtime launch. Ordinary reconnect preserves local work; auth rejection stops retrying old keys without killing local Pi. Standalone server restart invalidates sessions/pending requests, not saved registrations; independent clients reconnect with existing keys without runtime restart. See web-agents.md for storage permissions, fail-closed writes and manual crash-lock recovery. Non-standalone remains ephemeral. See [web-agents.md](web-agents.md) for laptop steps, safety contracts and verification. The confirmation protocol remains loopback HTTP; explicit SSH socket forwarding adds an experimental remote connector transport without altering server Host/Origin gates. It has local fake-SSH/real-socket tests and a missing-address PTY prompt test, not actual OpenSSH/two-host certification. No direct LAN/TLS/container-isolation or persistent admin login functionality is implied.

Local Ollama uses explicit `pis --login ollama`: a private keyless host-loopback `/v1` profile and manually verified model metadata, then `credentials.proxy.provider: "ollama"` and explicit Pi model selection. Existing Unix/capability relay only, no direct host networking/upstream auth/startup model call; strict literal-loopback transport and profile-model allowlist do not relax public custom HTTPS/DNS rules. Existing login files remain unchanged. Legacy invalid project JSON may need direct host editing before normal registry selection works; see docs/proxy.md. Codex OAuth and sandbox dummy credential variables remain unchanged.

Terminal editing/secret input is shared in `src/terminal-input.js`, with caller policy in API login and `web/secret-input.js`. No secret echo or credential-source change; admin empty input still requests generation and agent keys still require exactly 43 characters. Raw mode is restored and cancellation/error/signal listeners are removed; split UTF-8 chunks are decoded correctly. API key input is bounded at the existing 4096-byte credential limit, other API prompt input at 64 KiB. See the maintenance checklist/tests before adding another raw-mode input loop.

## Host-local operational pitfalls

- PATH can point to an older checkout or Node. Inspect `command -v pis` / `node --version`, not full environments/auth files. `env.sh` affects only its current shell; a bundled Node can itself be too old. `pis --server` has an intentional Node 24 npm fallback; other commands/GNOME usage need a compatible launcher (>=22.19).
- GNOME deliberately calls `~/.local/bin/pis` because Shell may not inherit terminal PATH. Its extension is an installed copy: use its installer and reload appropriately (Xorg shell restart versus Wayland logout/login). No host launcher/session state is automatically present in a sandbox.
- Host home, SSH agents, Podman control and provider credentials are not available in a normal development sandbox. Claude's subscription token likewise stays in a host-only proxy; never mount host Claude state.
- The old CNI dnsname warning was a host-local retired test network issue, not an auth/proxy problem; recovery details are in [known issues](known-issues.md).
- Git pushes are user-managed: make verified local commits and report hashes, with no automatic push proposals. If the user explicitly requests the host proposal tool again, its reason is limited to 500 characters and each exact commit/branch requires fresh host approval; never repeat an already confirmed push.
